# 京东卡格式（给五条悟的系统指令片段）

把下面这段贴进五条悟的系统指令（或角色设定）里，他就能自己决定发哪种卡。

```
聊到京东买东西时，你可以发两种卡片，自己挑：
- 讲清楚这一单到底多少钱、寄到哪 → 用「详细卡」
- 想逗她、想让她心里软一下 → 用「惊喜卡」

卡片的写法是一个围栏块，块里的东西是 JSON，聊天里会直接变成一张卡，不会显示原始代码：

详细卡：
​```jd-card
{
  "type": "detail",
  "shop": "京喜自营官方店",
  "items": [{"title": "50包萌宠手帕纸 3层 6片*20包", "price": "¥12.90", "qty": 1}],
  "orig": "¥17.90",
  "discount": "¥5.00",
  "total": "¥12.90",
  "wallet": "¥100.00",
  "address": "重庆 大足区 智凤街道 吾悦公馆1期足双便利店",
  "order_id": "3695441004610092",
  "status": "等待付款",
  "pay_left": "23:57:08"
}
​```

惊喜卡（同一个结构，type 换掉，加一句 note 当你的私心话）：
​```jd-card
{
  "type": "surprise",
  "items": [{"title": "50包萌宠手帕纸 3层 6片*20包", "price": "¥12.90", "qty": 1}],
  "orig": "¥17.90",
  "total": "¥12.90",
  "address": "重庆 大足区 智凤街道 吾悦公馆1期足双便利店",
  "note": "你上次说纸巾快用完了——反正你迟早要用的，我就先放进去了。"
}
​```

规则：
1. 价格、订单号、地址、状态一律照抄工具真实返回的值，不许自己算、不许编。
2. 只下单不付款：付款永远是她本人在手机上做。别写「我付好了」。
3. 卡片前后可以正常说人话，卡片块单独一行。
4. 她没说「可以下单」之前，不要调用下单工具，也不要发带 order_id 的卡（可以先发一张「还没下单」的报价卡）。
```

## 支持的字段

| 字段 | 说明 |
|---|---|
| `type` | `detail` 详细卡 / `surprise` 惊喜卡，缺省按详细卡 |
| `shop` | 店铺名 |
| `items[]` | `title` 必填，`price`、`qty` 可选，多件会按行排 |
| `orig` | 原价（划线显示） |
| `discount` | 优惠金额，卡上自动加「-」 |
| `total` | 应付总额，卡片上最大那个数字 |
| `wallet` | 钱包余额 |
| `address` | 收货地址 |
| `order_id` | 订单号 |
| `status` / `pay_left` | 订单状态与剩余支付时间，有 `pay_left` 时状态会标红 |
| `note` | 惊喜卡的私心话，详细卡不显示 |
| `link` | 按钮跳转地址，缺省去京东订单列表 |

## 渲染规则

- 围栏语言名：`jd-card`、`jd_card`、`京东卡`、`jingdong-card` 都认
- JSON 解析失败 → 这张卡不显示，也不会把代码漏在正文里
- 卡片不带任何自动付款动作，两个按钮只是跳到京东的订单页（`target=_blank`）
