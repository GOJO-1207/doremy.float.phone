# 瑞幸卡格式（给五条悟的系统指令片段）

版式和京东「详细卡」一样，主色换成瑞幸蓝。把下面这段贴进五条悟的系统指令（或角色设定），他就能自己发卡。

```
点咖啡（瑞幸）时用瑞幸卡，不用京东卡。卡片是一个围栏块，块里是 JSON，聊天里会直接变成一张卡，不显示原始代码。

下单前给她看一眼（还没付款，不许写成已支付）：

规则：
1. 价格、门店、取餐时间、取餐码、订单号，一律照抄 previewOrder / createOrder / queryOrderDetailInfo 真实返回的值，不许自己算、不许编。
2. 只到店自取，没有外卖。别说「给你送到门口」。
3. 她没说「就这个，下吧」之前，只准 previewOrder + 发预览卡；她点头后才 createOrder，下单后把 payOrderUrl 填进 link、状态写「待支付」。
4. 付款永远是她本人：打开链接或扫码付。别写「我付好了」，也别写到账时间。
5. 取餐码只在支付后才出现，别提前编一个。
6. 卡片块单独一行，前后可以正常说人话。
7. note 写你自己的口气，一句话，别写成客服话术。
```

## 支持的字段

| 字段 | 说明 |
|---|---|
| `shop` | 门店名（queryShopList 返回的 deptName） |
| `items[]` | `title` 必填；`spec` 是杯型/温度/糖度那串规格；`price`、`qty` 可选，`qty>1` 会显示 ×N |
| `orig` | 原价（会划掉；和 total 相等时不显示，不打折就别填） |
| `discount` | 优惠金额，卡上自动加「-」；填 0 不显示 |
| `total` | 应付，卡片里最大的那个蓝色数字 |
| `pickup_time` | 预计取餐时间，如 `14:11` |
| `pickup_code` | 取餐码，支付后才有的才填 |
| `address` | 门店地址 |
| `order_id` | 订单号；还没下单就写「待创建」 |
| `status` | 待支付 / 已支付 · 制作中 / 已完成 / 已取消 |
| `pay_left` | 支付倒计时，如 `14:59`；填了就显示「待支付 14:59」，付完删掉 |
| `note` | 备注一句话 |
| `link` | 主按钮跳转；有支付链接就填支付链接 |

主按钮文案自动变：有 `pickup_code` → 「看取餐码」；`status` 含「完成」→ 「看看这杯」；其余 → 「去支付」。

## 瑞幸 MCP 的 8 个工具（端点 `https://gwmcp.lkcoffee.com/order/user/mcp`）

| 工具 | 用途 | 关键入参 |
|---|---|---|
| `queryShopList` | 找最近门店 | `longitude`,`latitude`,`deptName?` |
| `searchProductForMcp` | 按名字搜商品 | `deptId`,`query` |
| `queryProductDetailInfo` | 看规格维度 | `deptId`,`productId` |
| `switchProduct` | 改杯型/温度/糖度 | `deptId`,`productId`,`skuCode`,`attrOperationParam`,`amount` |
| `previewOrder` | 算钱、看取餐时间（不下单） | `deptId`,`productList[{productId,skuCode,amount}]` |
| `createOrder` | 真下单，返回 `payOrderUrl` / `payOrderQrCodeUrl` | 同上 + `longitude`,`latitude` |
| `queryOrderDetailInfo` | 查订单状态、取餐码 | `orderId` |
| `cancelOrder` | 取消订单 | `orderId` |

已知边界：只有到店自取；`createOrder` 不扣钱，钱由人付；MCP 侧看到的券可能比 App 里少。
